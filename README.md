# FCMG_DB
Databricks project 

## Architecture

The project follows a Databricks Medallion Architecture to transform raw SportsBar operational data into analytics-ready datasets for the parent organization, Atlikon.

### Data Flow

OLTP (SportsBar) → Amazon S3 → Lakeflow Jobs → Bronze → Silver → Gold → Analytics & Serving

### Source System

SportsBar's OLTP system acts as the primary source of transactional data. The data is extracted and stored in Amazon S3 for further processing.

### Raw Data Storage

Amazon S3 is used as the landing zone for raw data. Historical data is retained to support reprocessing, auditing, and recovery requirements.

### Ingestion and Processing

Databricks Lakeflow Jobs are used to orchestrate the ingestion pipeline. Data is loaded from S3 and processed through the different stages of the Medallion Architecture.

### Bronze Layer

The Bronze layer stores raw or near-raw data with minimal transformations.

Key responsibilities:
- Preserve source data
- Maintain historical records
- Provide data traceability
- Support reprocessing

### Silver Layer

The Silver layer contains cleaned and standardized data.

Key responsibilities:
- Data cleansing
- Data validation
- Schema standardization
- Applying transformation and business rules
- Preparing reliable datasets for analytics

### Gold Layer

The Gold layer contains curated, business-ready datasets.

Key responsibilities:
- Business-level transformations
- Aggregations and KPIs
- Analytical data modeling
- Preparing datasets for reporting and downstream consumption

### Parent Organization Analytics

The Gold data generated by the SportsBar child organization is made available to the Atlikon parent organization for higher-level analytics and reporting.

### Serving and Consumption

The curated Gold datasets can be consumed by:

- Databricks Dashboards
- Power BI
- Databricks Genie
- Business users and analytical applications

### Databricks Components

| Component | Purpose |
|---|---|
| Amazon S3 | Raw and archival data storage |
| Databricks Lakeflow Jobs | Data ingestion and orchestration |
| Bronze Layer | Raw data storage |
| Silver Layer | Cleaned and standardized data |
| Gold Layer | Curated and business-ready data |
| Unity Catalog | Data governance and cataloging |
| Databricks Genie | Natural-language data analytics |

### Key Design Principles

- Separation of ingestion, transformation, and serving layers
- Historical data preservation
- Data quality and validation
- Reusable transformation logic
- Centralized data governance
- Business-ready datasets for downstream analytics
